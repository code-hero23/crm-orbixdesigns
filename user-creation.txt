1. Which Statuses Are Sent Back?

The CRM maps internal lead statuses to Meta Conversion events (defined in leads.controller.ts):

CRM Status	Meta Event Name	Purpose / Significance
Fresh	Lead	Initial lead recorded
Yet to Follow-up	LeadAwaitingFollowUp	Lead queued for follow-up
Follow-up	LeadModerate	Lead engaged in follow-up discussions
Opportunities	Contact	Qualified prospect / opportunity stage
Order Booked	Purchase	Converted sale (sends lead's orderValue in INR)
Disqualified	DisqualifiedLead	Unqualified lead signal for ad algorithms

(Any status not listed in the table above is ignored and not sent to Meta).

2. How Are They Sent Back?

When a lead's status is updated (via PUT /api/v1/leads/:id):

Condition Check:

The lead must have a metaLeadId (Facebook Lead ID). If the lead was added without a metaLeadId, the event is skipped.
The new status must match one of the mapped statuses above.

Payload Prepared & Anonymized:

In meta.service.ts, user data is hashed using SHA-256 (Meta privacy standard):
SHA-256 hashed phone
SHA-256 hashed email
lead_id (metaLeadId)
Client IP and User Agent
For Order Booked (Purchase), it attaches currency: 'INR' and the lead's orderValue.

API Call:

Dispatches an asynchronous POST request to Meta's Conversions API endpoint:
https://graph.facebook.com/v18.0/{META_PIXEL_ID}/events
It runs non-blockingly so any Meta API failure won't interrupt the user's CRM operation.
